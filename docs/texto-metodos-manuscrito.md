## Experimental artifact and source representation

We used the ontology schema documented in a previous oncology-focused work as the source representation, without modifying its original OWL/XML artifact. A versioned, synthetic OWL/XML overlay was created to represent explicit Patient–Evolution–Examination links, exam dates and textual units in a test-only namespace. The converter reuses verified class and property IRIs from the original ontology, but the generated cases do not include clinical records or patient identifiers from the original study. The original archive was checked using SHA-256 before and after processing. All extensions and source-to-target correspondence rules were documented separately.

## Conditions

Condition A applied a deterministic, rule-based converter to the test-only OWL/XML overlay. The converter emitted FHIR R4 Patient and Observation resources, while refusing occurrences with ambiguous patient links, missing examination identity, invalid dates, unsupported datatypes or multiple results. Refusals were retained in the coverage denominator. Condition B validated the same FHIR outputs with the official HL7 FHIR Validator CLI version 7.0.3, FHIR release 4.0.1, and the core package `hl7.fhir.r4.core#4.0.1`, using the base Bundle profile and disabling external terminology service access. Condition C combined B with explicit comparisons of source facts and target facts against predefined synthetic reference expectations. The conditions assess fault signaling, not automatic remediation.

## Preliminary pilot (historical V3)

An engineering pilot previously generated 11 source occurrences, five converted observations and six explicit refusals. The corrected FHIR reference Bundle, seven individual resources and eight mutation cases were submitted to the official validator: 16 operations completed, 14 without errors and two containing errors. The reference Bundle passed without errors. Among seven semantically targeted mutations, one violated the Bundle uniqueness invariant through duplication of `fullUrl`, whereas six did not produce FHIR conformance errors. These are descriptive observations on one shared synthetic baseline, not an estimate of general sensitivity or clinical generalization. The V3 files, execution logs and individual SHA-256 values are retained as immutable-by-convention baseline artifacts.

## Expanded benchmark (prospective V4)

To extend the range of test situations without assuming that mutations represent independent patient records, we designed 26 purposively selected synthetic source families. Twenty families contain information eligible for deterministic transformation and six were designed to exercise explicit refusal behavior. Each convertible family has a baseline conversion, one controlled mutation and one semantically equivalent control; refusal families contain only a baseline. This produces 66 fixed FHIR Bundle inputs. Eight families were allocated to development and 18 to evaluation before running official HL7 validation on V4. The benchmark includes numeric and textual values, missing results and dates, varying date precision, repeated examinations, patient identity associations, omission, unsupported additions and structural controls. The gold record is stored separately from converter code, and cases are identified by stable file hashes.

The semantic comparison examines patient associations, examination identity and occurrence, values, explicitly recorded units, and dates with preserved precision. Queries Q01–Q05 are evaluated through separate routines on explicit OWL/XML assertions and FHIR resources; Q06 inventories lost or nonrepresented information. Each result is classified as accepted, refused, detected, not detected or uninterpretable. The pairwise mutation effect is estimated only for families whose baseline passes official conformance validation. Detection precision, recall and false-alarm counts will be reported by error class with family-based denominators, while source refusals remain separate from validator false positives. No inferential significance testing or clinical validity is claimed at this phase, and expert adjudication of the synthetic gold is planned before using the benchmark to support broader conclusions.

## Limitations that must remain explicit

The benchmark cases and their gold references were initially designed with AI assistance, without independent domain-expert adjudication. The use of separate comparator code avoids direct implementation reuse but does not eliminate shared-specification error. The cases are purposefully selected, small and dependent within families. Core FHIR validation with `-tx n/a` does not certify full terminology conformity, national implementation guides or the clinical appropriateness of mapped codes. Exact equivalence holds only for the fields represented and the queries tested, not for all ontological axioms or inferred knowledge. Results from the V3 pilot must not be pooled with V4 as independent observations.
